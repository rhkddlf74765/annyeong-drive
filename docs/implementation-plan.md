# 1차 제출 구현 순서

목표: 2026-11-14 제출(마감 11/15 23:59). 기준: `docs/decisions-2026-11-11.md`.
순서 원칙: 판단 핵심(테스트 가능) → 데이터 → 화면 → 차량 신호 연결 → 통합 확인 → 제출.
에뮬레이터는 9단계의 통합 확인과 영상 녹화 때만 켠다. 그 전 단계는 JVM 단위 테스트와 Compose Preview로 확인한다.
영상 동작 범위가 회의에서 정해지면 5~8단계의 순서와 범위를 다시 맞춘다.

## P0 (1차 제출 필수)

### 0단계. 기존 코드 분류 (11/11) — 코드 변경 없음
- [ ] `main`의 각 파일을 "옮겨 재사용할 판단·어댑터" / "확인용 하네스(src/debug로)" / "새 구조로 대체"로 나눈 표를 보고한다.
- [ ] 기존 테스트(ZoneDetector, AnnouncementManager, DriveSession)가 무엇을 보장하는지 요약한다.
- [ ] 기존 문구 중 도메인 원칙(30 고정 등)과 충돌하는 곳을 표시한다.

### 1단계. 판단 핵심: DriveCoordinator (11/11)
- [ ] 패키지 구조 확정.
- [ ] `DriveEvent`, `DriveState`(상태 패턴), `DriveAction` 정의.
- [ ] 입력 인터페이스와 가짜 구현: `GearSource`/`FakeGearSource`, `SpeedSource`, `UxRestrictionSource`, `SeatBeltSource`, `FuelTypeSource`, `Clock`.
- [ ] 시나리오 테스트
  - [ ] 주정차 경고 구역 안에서 P를 넣으면 주정차 경고만 나오고 이어 보기는 나오지 않는다.
  - [ ] 퀴즈 중 D로 바꾸면 교육 화면 닫기와 학습 음성 중단이 함께 나온다.
  - [ ] UX 제한이 걸리면 기어와 상관없이 교육 화면이 닫힌다.
  - [ ] 미완료 교육이 있는 상태로 정차하면 이어 보기 제안이 나온다.
  - [ ] 대여 설정이 끝나면 교육 시작 화면 열기가 나온다.
  - [ ] 착좌 해제만으로는 초기화하지 않는다.
- 완료 기준: 테스트 통과, Android import 없음.

### 2단계. 데이터: 두 Aggregate와 저장소 (11/11~12)
- [ ] 의존성 추가 승인: kotlinx.serialization 플러그인, DataStore(Preferences).
- [ ] `RentalSession`(운전자 데이터 루트) + `LearningProgress`: 답하기, 건너뛰기, 이어 볼 위치, 처음부터 보기(복습 유지), 복습 목록.
- [ ] `VendorConfig`(업체 데이터 루트) + `AdminCredential`: 최초 코드 설정, 해시 검증, 실패 횟수와 잠금, 반납 예정 + N시간 경과 판단.
- [ ] JSON 직렬화(`schemaVersion`, `contentVersion` 처리)와 저장소 2개(`driver_session`, `vendor_config`), 앱 전체 공유 인스턴스.
- [ ] 백업 제외 설정.
- 완료 기준: 도메인 규칙과 직렬화 왕복 테스트 통과.

### 3단계. 서비스 골격과 확인용 코드 이동 (11/12)
- [ ] 확인용 `LocationService` 등을 `app/src/debug/`로 이동.
- [ ] 새 Foreground Service: 어댑터 → Coordinator → 실행기(음성, 알림, 화면 상태 StateFlow) 연결.
- [ ] 앱 시작 시 예비 초기화 확인.
- 완료 기준: 빌드 성공, 기존 테스트 유지.

### 4단계. 업체 설정 화면 + 반납 처리 (11/12)
- [ ] 업체 설정 화면(최초 코드 설정, 이후 코드 입력 후 진입, 잠금).
- [ ] 정차 중 "반납 완료" → 관리자 코드 → 운전자 데이터 초기화 → 대기 상태.
- 완료 기준: 단위 테스트 + Preview. 시연용 코드는 README에 기록할 값으로 정한다.

### 5단계. 대여 시작: 언어 선택 + 출발 전 점검 (11/12)
- [ ] 언어 선택(한국어·영어).
- [ ] 출발 전 점검: 전 좌석 안전띠(수동 확인 + 경고 좌석 보조 안내), 유종(업체 설정), 하이패스 확인 안내, 반납 조건.
- [ ] 점검 완료 후 교육 시작 화면 자동 진입.
- 완료 기준: 안전띠 "경고 없음"에서 "모두 착용"이 표시되지 않는 테스트 포함.

### 6단계. 교육·퀴즈 (11/13)
- [ ] 콘텐츠 모델(카드, 문항, 해설)과 문구 ID. 한국어 원문을 `strings.xml`에.
- [ ] 교육 카드 A-1~A-6(임시 그림).
- [ ] 핵심 퀴즈 5문항: 정답 확인 전 답 변경 가능, 확인 후 변경 금지, 건너뛰기는 미완료, 결과 화면({완료 수}는 응답한 문항 수).
- [ ] 복습 화면("다시 볼 규칙").
- 완료 기준: 진행 저장 연동 테스트 + Preview.

### 7단계. 교육 중단·재개와 주행 중 화면 제한 (11/13)
- [ ] 실제 `CarUxRestrictions` 어댑터.
- [ ] 주행 진입 시 화면 닫기 + 학습 음성 중단 실행.
- [ ] 정차 시 "이어서 확인할까요?"(이어 보기 / 처음부터 보기 / 나중에 보기).
- [ ] 부록 E 문구(차량 상태 확인 중, 불러오기 실패, 음성 미지원 → 화면으로 계속).

### 8단계. 주행 중 규칙 안내와 주정차 경고 이전 (11/13)
- [ ] 기존 `ZoneDetector`·`AnnouncementManager` 판단을 Coordinator 흐름으로 연결(다시 쓰지 않고 옮긴다).
- [ ] 문구 원칙 반영: 30 고정 제거, 값이 있을 때만 숫자, 처음 2문장·이후 1문장, 중복·만료 처리.
- [ ] 주정차 경고: P 전환 순간 100m 안 검수 구역이면 음성 + heads-up 알림, 확인을 요청하는 문구.

### 9단계. 통합 확인과 공통 시험 (11/13 밤)
- [ ] 에뮬레이터 확인 1: 어댑터(UX 제한, TTS, 위치)가 Coordinator까지 들어오는가.
- [ ] 에뮬레이터 확인 2: 내비 위 알림, 주행 시 교육 화면 닫힘, 정차 시 이어 보기.
- [ ] 공통 시험 6종: 중복, 만료, 경로 변경, 내비·통화 충돌, UX 제한, 반납 후 삭제.

### 10단계. 영어 문구와 제출 (11/14)
- [ ] `values-en` 영어 문구(번역이 도착하면).
- [ ] README(앱 이름, 한 줄 소개, 실행 방법, 테스트 환경, 업체 설정·시연용 관리자 코드, APK 위치).
- [ ] release APK 서명, GitHub Releases 업로드, 심사 계정 초대.
- [ ] 시연 영상 1~2분 녹화(GPX·시험 이벤트와 실제 신호를 구분해 표시).

## 일정이 밀릴 때 줄이는 순서
1. P1 전체를 기획서의 확장 계획으로 돌린다.
2. 6단계의 교육 카드는 A-1~A-3만 남긴다.
3. 4단계 업체 설정 화면은 시연용 기본값 파일로 대체하고, 반납 처리(관리자 코드)는 유지한다.
4. 영어 문구가 늦으면 한국어 화면 + 영어 음성으로 시연한다.
