## 2. 구조: Coordinator

- 이유: 정차 순간 여러 기능이 경쟁하고(주정차 경고 > 오주유 > 이어 보기), 주행 진입 시 "화면 닫기 + 음성 중단"을 빠짐없이 해야 한다. 각 화면이 차량 상태를 보고 스스로 판단하면 규칙이 흩어져 "경고와 이어 보기가 동시에 뜸", "화면은 닫혔는데 음성이 계속됨" 같은 버그가 생기고, 에뮬레이터로만 잡힌다.
- 판단을 한 곳(DriveCoordinator)에 두면 이벤트 목록을 넣는 시나리오 테스트로 검증할 수 있다. 기존 코드가 확인용이라 전환 비용이 작다.
- 처음에는 P0 이벤트만 넣는다: 기어 변경, 차속, 정차 위치, 보호구역·카메라, UX 제한, 반납 버튼.

## 3. 상태와 우선순위

- 상태: 대기 → 대여 설정(언어 선택 → 출발 전 점검) → 정차 ↔ 주행 → 반납 처리 → 초기화 → 대기.
- 정차 진입: 기어 P + 차속 0. 정차 순간 우선순위: 반납 처리 > 검수된 주정차 경고 > 주유소(오주유, 플래그 켜짐) > 미완료 교육 이어 보기 > 일반 정차.
- 교육 화면: P + 차속 0 + UX 제한 없음일 때만 연다. D/R, 차속, UX 제한 중 하나라도 생기면 팝업 없이 화면을 닫고 학습 음성을 멈춘다. 이어 보기는 다음 정차에서만.
- 대여 설정이 끝나면 교육 시작 화면을 자동으로 띄운다("나중에 보기" 가능).
- 초기화: 반납 처리 완료 또는 앱 시작 시 반납 예정 시각 + N시간 경과. 착좌 해제만으로는 지우지 않는다.

## 4. 진행 저장

- 의미: 교육·퀴즈를 어디까지 봤는지를 기기에 기록한다. 이어 보기, 건너뛴 문항 유지, 복습 화면, "확인한 내용은 이번 대여 동안 저장돼요" 문구가 모두 여기에 기댄다. 시동을 끄면 앱이 종료되므로 메모리가 아니라 기기에 저장한다.
- 형식 규칙
  - 대여 하나가 단위. 위치·개인정보는 넣지 않는다.
  - 식별자는 순서 번호가 아니라 고정 문자열(`quiz.lane_direction`).
  - `schemaVersion`(저장 구조), `contentVersion`(문구 내용). 콘텐츠 버전이 다르면 진행을 버리고 새로 시작.
  - 이번 회차(`attempt`)와 복습 목록(`reviewIds`)을 분리. "처음부터 보기"를 해도 복습·미완료는 유지.
  - `correct`는 복습 목록에만 쓰고 점수로 보여 주지 않는다.
- 저장 방식에서 지킬 것
  1. 파일 분리: `driver_session`(운전자) / `vendor_config`(업체). 초기화는 `driver_session`만 비운다.
  2. 파일마다 DataStore 인스턴스는 하나(앱 전체 공유). 서비스와 화면이 각자 열면 예외로 앱이 죽는다.
  3. 답하거나 건너뛸 때마다 즉시 저장.
  4. 예비 초기화는 타이머가 아니라 앱 시작 시 확인.
  5. `allowBackup="false"` + `dataExtractionRules`로 백업 제외.
  6. AAOS 사용자 프로필별 저장은 시연 범위에서 문제없음. 실차 적용 시 업체 설정 위치는 확장 과제.
- 직렬화 플러그인 버전은 Kotlin 버전과 맞추고, 런타임 라이브러리는 호환 버전을 확인한 뒤 넣는다.

```json
{
  "schemaVersion": 1,
  "rentalId": "생성한 UUID",
  "startedAt": "2026-11-11T09:00:00+09:00",
  "language": "ko",
  "drivingCountry": null,
  "contentVersion": "2026-11-10",
  "attempt": {
    "number": 1,
    "position": { "screen": "quiz", "itemId": "quiz.no_signal_crosswalk" },
    "items": {
      "quiz.lane_direction": { "status": "ANSWERED", "correct": true },
      "quiz.school_zone_stop": { "status": "SKIPPED" }
    }
  },
  "reviewIds": ["quiz.school_zone_stop"],
  "viewedCardIds": ["card.seatbelt_all", "card.keep_right"]
}
```

## 5. 반납 처리와 업체 설정

- 정차 중 "반납 완료" → 관리자 코드 입력 → 입력값을 해시해 저장된 해시와 비교 → 맞으면 운전자 데이터 초기화.
- 코드는 앱 코드에 쓰지 않는다. `vendor_config`에 SHA-256 해시와 기기별 무작위 salt만 저장. 시연용 코드는 README에 적는다.
- 기본 5회 실패 시 30초 잠금(설정 값). 업체 설정 화면 진입에도 같은 규칙.
- 업체 설정 항목: 유종, 반납 장소·시각, 연료·배터리 기준, 하이패스 이용 여부·정산 방식, 업체 연락처, 예비 초기화 시간 N, 관리자 코드.
- 처음 설치 시(해시 없음)에만 코드를 새로 정한다. 이후에는 코드를 입력해야 들어간다.
- 초기화 범위: 언어·국가 설정, 교육 진행, 안내 기록은 지운다. 차량 정보·반납 조건·코드 해시는 남긴다.
- 의도: 반납 확정은 업체가 해야 운전자의 실수 삭제를 막는다. 예비 초기화는 직원이 잊었을 때 이전 손님 기록이 남지 않게 하는 안전장치다.

## 6. 데이터 세 칸

| 칸 | 내용 | 보관 |
| --- | --- | --- |
| 운전자 데이터 | 언어, 운전 국가, 교육 진행, 안내 기록 | 기기에만, 반납 시 삭제 |
| 업체 데이터 | 차량 정보, 반납 조건, 코드 해시 | 업체가 관리, 초기화하지 않음 |
| 업체 전달 데이터 | 개인 식별 없는 집계 | 운전자 동의 시에만 (1차 범위 밖) |

- 이유: 안내 기록(언제·어디서 어떤 안내를 받았는지)은 대여 계약과 묶이면 특정인의 위치·시간 기록이 되고 위반 정황으로 읽힐 수 있다. 운전 국가는 국적을 짐작하게 한다. "감시·평가하지 않는다"는 원칙을 지킨다.

## 7. 안전띠

- 좌석별 미착용 경고가 참이면 그 좌석에 사람이 앉아 안전띠를 안 맨 것이다. 경고가 없다는 것은 맨 것 / 빈 좌석 / 센서 없는 좌석(뒷좌석에 흔함) / 인식 못 함 중 무엇이든 될 수 있다.
- `SeatBeltSource`는 좌석별 `UNKNOWN` / `WARNING` / `NO_WARNING`을 돌려준다. 점검 완료 판단에서 `NO_WARNING`은 `UNKNOWN`과 같다. 지금은 가짜 구현이 항상 `UNKNOWN`.

| 상황 | 화면 동작 |
| --- | --- |
| 신호 확인 전 | 수동 체크만 |
| 어떤 좌석에 경고 | 그 좌석 안내 추가. 수동 확인은 그대로 |
| 경고 없음 | 추가 표시 없음. "모두 착용" 금지. 수동 확인은 그대로 |

- 주행 중 안전띠 경고는 차량이 하므로 앱은 출발 전 점검에서만 다룬다.

## 8. 확장 대비와 임시 처리

- 국가별 차이: 문구를 (규칙 ID, 언어, 운전 국가)로 찾고, 없으면 (규칙 ID, 언어) → 기본 언어 순으로 떨어진다. 운전자 설정에 `drivingCountry: String?`만 두고 지금은 null.
- 오주유 뼈대: `FuelTypeSource`(지금은 업체 설정 값), `isNearGasStation()`(시연 지역 좌표), 정차 판단 안의 `fuelGuardEnabled` 분기. 철회 시 플래그를 끄거나 분기만 지운다.
- 문구: 문구 ID로 `strings.xml`. 기본 `values`는 한국어 원문, 영어는 `values-en`. 번역이 생기면 파일만 추가.
- 그림: `card_school_zone` 같은 고정 이름 리소스에 임시 그림. 나중에 교체.
- 음성: Pleos TTS ON_DEVICE는 영어만 확인됨. 선택 언어 음성이 안 되면 "화면으로 계속"(부록 E).
